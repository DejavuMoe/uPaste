# Threat model

## Scope and trust boundaries

Protected assets include Share content, owner capabilities, encryption keys, service availability, persistence integrity, and application-origin authority. Boundaries are browser-to-app, browser-to-file-origin, reverse-proxy-to-listeners, process-to-database/filesystem, operator/backup access, and third-party networks. Anonymous Standard/Encrypted Text and Standard File creation, read, owner update, and delete in addition to Standard raw and `/healthz` are implemented. Strict payload validation, expiration enforcement, capability verification, inert Text delivery, attachment-only File delivery, process-local rate limiting, File concurrency gates, and periodic maintenance purge/reconciliation are implemented. Public mode adds Cap or Turnstile challenge verification for anonymous creation, creation-anchored finite retention, a non-secret runtime configuration endpoint, and one Superadmin governance surface bounded to inspection and deletion. Rate limits remain process-local and reset on restart, there is no distributed DDoS protection or hard storage quota, and public exposure therefore still depends on the operator's reverse proxy and challenge provider rather than on uPaste alone.

Encrypted Text Shares hide plaintext from the application server when correctly used; V1 File Shares are Standard only. Encrypted text does **not** hide metadata the server necessarily observes: ciphertext size, timestamps, resource ID, expiration, request IP/headers, access timing, and traffic relationships. A malicious administrator can alter served JavaScript and steal future plaintext or keys; browser-delivered zero knowledge cannot prevent that.

## Threat analysis

| Threat | Asset and trust boundary | Attack and impact | Planned mitigation |
|---|---|---|---|
| Stored XSS | Application origin; stored text to viewer browser | Persisted script executes for later readers, stealing capabilities or acting as the app | Phase 2 JSON uses standard escaping and raw delivery is `text/plain`, `nosniff`, sandboxed CSP with no rendering. Markdown HTML remains disabled; any future rendered output requires sanitization. |
| Reflected XSS | Request input to app response | Crafted URL/input is reflected as executable markup | Context-aware framework escaping, no unsafe HTML sinks, CSP, and tests for reflected inputs. |
| Markdown injection / unsafe HTML | Markdown parser/render boundary | Links, raw HTML, or malformed markup create script or deceptive content | Disable raw HTML, sanitize renderer output independently, constrain URL schemes, forbid automatic remote media, and keep rendering non-executable (ADR 0013, FRONTEND_PRODUCT_SPEC). |
| Malicious SVG/HTML/JS/XML uploads | File origin to browser | Active content executes and attempts origin-level compromise | Separate origin and listener, `Content-Disposition: attachment` for every File, CSP, and no app-origin file delivery. |
| MIME confusion / active uploads | Upload input and file response | Extension or declared type tricks browser into executing HTML/SVG/JS | Sniff up to 512 bytes with `http.DetectContentType`, distrust declared MIME and extensions, send `nosniff`, sandbox headers, and `Content-Disposition: attachment` for every File. No malware detection is claimed. |
| Path traversal / symlink | Object storage filesystem boundary | Filenames, keys, symlinks, or wrong types trick reads/writes outside object root | File objects use generated canonical hex keys and fixed shards; filenames are basename metadata only; roots/shards/final objects reject symlink/non-regular use and use restrictive modes. |
| Resource ID enumeration | Public network to Share reads | Guessing IDs reveals Standard Shares | Independent 128-bit `crypto/rand` IDs encoded as 22-character unpadded base64url and generic failures; IDs remain identifiers, never authorization secrets. Process-local rate limiting bounds automated enumeration attempts. |
| Owner-token theft | Browser/app management boundary | Stolen capability permits deletion or other owner actions | Independent 256-bit `crypto/rand` token with `up_o1_` prefix, HTTPS, bearer header only, least-power operations, no persistence of raw token, and constant-time verifier comparison. |
| Token leakage through URLs | Browser history, Referer, logs, analytics | Credential in URL propagates to third parties and infrastructure | Management reads only one Authorization bearer header; query/path/body/cookie tokens are ignored. Creation `Location` contains only the public ID. Phase 6 frontend never persists or transports OwnerToken in history.state, React Router location.state, browser storage, or URLs (ADR 0013). |
| Logging leakage | Requests/errors to operators and log systems | Sensitive headers or bodies are recorded | Structured logs contain safe operation context only; handlers never log bodies or Authorization, and `OwnerToken` implements redacted `slog` formatting. Regression tests ensure generated, valid, and invalid owner candidates and parser input do not appear in logs/errors. |
| Database theft | Filesystem/backup to attacker | Standard content, Encrypted ciphertext, metadata, and SHA-256 owner-token verifiers are exposed | New data directories/database files use `0700`/`0600`; deployments still require least privilege and protected backups. Uniform 256-bit owner tokens make offline preimage search infeasible without a pepper; content and metadata exposure remains documented. |
| Malicious server administrator | Host/operator to process, files, and served frontend | Reads Standard content/metadata or modifies frontend to capture encrypted plaintext/key | Encrypted mode keeps reviewed-protocol plaintext out of storage, but cannot protect against malicious JavaScript served by that administrator. Disclose limits and pursue secure/reproducible releases and TLS/integrity operations. |
| Brute force | Public network to IDs/tokens | Repeated guesses discover Shares or capabilities | 128-bit random IDs, independent 256-bit random owner tokens, constant-time SHA-256 verifier comparison, generic responses, and process-local rate limiting. Distributed rate limiting and monitoring remain required before unrestricted Internet exposure. |
| Upload/storage abuse | Anonymous client to disk | Fills disk, stores prohibited payloads, or creates excessive objects | Bounded File sizes/transfers, process-local IP limits, File gates, expiry purge, and stale orphan reconciliation reduce exposure. Public mode always expires content, while private-mode Shares may be non-expiring and retain storage risk. No hard quota, malware detection, moderation, or distributed limiting exists. |
| Slow File transfer / DoS | Public network to bounded File paths | 64 MiB transfers fail under an impractically short absolute deadline or connections remain indefinitely active | Ordinary reads/writes remain 15 seconds; only valid multipart File body reads and File responses receive bounded 10-minute deadlines. Process-local rate limits and File concurrency gates bound transfer load; hard quotas remain out of scope. |
| Oversized or ambiguous JSON | Client to parser/memory/disk and authorization boundary | Unbounded, duplicate, invalid-UTF-8, or differently cased input causes exhaustion or inconsistent interpretation | A bounded reader rejects JSON wire bodies above 2 MiB; strict Go JSON v2 rejects duplicate names, invalid UTF-8, unknown/case-mismatched members, malformed JSON, and trailing values; decoded text and SQL are limited to 1 MiB. Owner verification precedes PATCH body processing and is repeated transactionally. |
| Decompression/resource bombs | Uploaded/encoded data to processors | Tiny input expands or consumes excessive parser resources | Do not auto-extract archives; bound compressed and expanded input/time for any future processing; reject unsupported content encodings. |
| CSRF | Third-party site to management API | Browser is induced to perform owner action | No auth cookies; bearer token in an explicit header; same-origin API; validate Origin on sensitive browser requests where applicable. |
| CORS mistakes | Foreign origin to API | Permissive policy exposes responses or enables credential use | Send no permissive CORS by default; explicit narrow allowlist only after a documented use case; never reflect arbitrary origins. |
| SSRF | User input to server outbound network | Server fetch reaches metadata/internal services | No URL fetching or server-side previews; avoid outbound fetch features. If scope changes, use strict destination and redirect controls. |
| Unsafe redirects | User-controlled target to browser | Open redirect enables phishing or leaks fragment/query data | Avoid user-controlled redirects; permit only validated local paths or explicit origins; never forward capabilities. |
| File/app origin confusion and proxy Host spoofing | Reverse proxy to distinct loopback listeners | File content executes with application authority or spoofed Host creates hostile download links | Separate listeners, configured file-origin, app listener without `/f`, file listener without API/raw, no Host/forwarded-header URL construction, attachment-only policy, and explicit proxy routes. |
| Spoofed forwarded headers | Client/proxy to app | Forged IP changes limiter identity | Ignore forwarded headers unless immediate TCP peer is in configured trusted CIDRs; malformed XFF falls back to peer. Incorrect trusted ranges permit spoofing. |
| Fragment theft | Browser history/sync, clipboard, screenshots, extensions, page JavaScript | Complete Encrypted Share URL reveals its AES key and plaintext | Keep the key only in the URL fragment, never send/store it server-side or in browser storage, minimize third-party code, and disclose that anyone with the complete URL can decrypt. |
| Nonce reuse | Browser crypto boundary | Reusing a GCM nonce with one key can destroy confidentiality/integrity | Official helper generates a fresh independent 96-bit nonce for every create/update encryption. Server validates length but cannot prove uniqueness or client key reuse. |
| Ciphertext tampering | Storage/network to browser | Modified payload is shown as authentic text | AES-256-GCM with a 128-bit tag and frozen AAD; decryption rejects changed nonce, ciphertext, tag, envelope, format, or UTF-8. |
| Stale/expired access | Clock/database to read/mutation paths | Content remains readable or is revived after expiration/deletion | Shared active loading derives `now >= expires_at` from one injected server clock on JSON/raw/mutations. Expired rows return 410 and cannot be revived/deleted; owner delete physically cascades payload removal. |
| Missing/orphan/temp objects | Database/object lifecycle boundary | Crash/failure leaves bytes unreachable or live metadata lacks bytes | DB resolves every File before serving; missing live object is a 500, never 404. Compensation is registered before finalization, including publish-then-error failures; failed compensation, post-delete, and crash-window orphans remain inaccessible and are cleaned up by Phase 5 periodic local object reconciliation. |

IPv6 limiter keys aggregate /64 to reduce privacy-address rotation bypasses. Distributed attacks and restarts can evade process-local limits. Reconciliation grace protects ordinary filesystem-finalization/SQLite-commit windows; unknown filesystem entries and missing referenced objects are retained for operator investigation.

## Residual risks

Traffic analysis and server-visible metadata remain. Availability cannot be guaranteed against an attacker with enough resources. Host compromise defeats Standard privacy and can compromise future browser sessions. Operational backup deletion is controlled by deployers, not the Share lifecycle engine.
